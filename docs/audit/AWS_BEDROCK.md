# AWS / Bedrock research (brief §6, §7.6)

Agent: aws-bedrock research. Date: 2026-11-26. CMDeck pinned at `4a2f27d590`.
Every AWS claim links to the page it came from (all accessed 2026-11-26). "(unverified)" means the
claim was not confirmed on an official page during this audit. Kiro Crew's AWS code is out of scope
(separate agent).

**Bottom line.** CMDeck already runs agents on Bedrock with no AWS code of its own. Claude Code,
Codex and OpenCode each talk to Bedrock themselves, and CMDeck passes per-instance environment
variables (with secret references) to them. The smallest useful AWS module is **documentation and
configuration, not code**: a Bedrock section in the provider docs, plus guidance for enabling
AWS-maintained MCP servers as agent tools. Native Bedrock or AWS UI (KB browser, Guardrails tester,
AgentCore console, S3 drive, EC2 launcher) is not justified for one user while the AWS console and
AWS MCP servers already cover it.

**Finding (risk):** provider processes inherit the server's `process.env`
(`Drivers/ClaudeDriver.ts:125` `mergeClaudeProcessEnvironment(config, environment, process.env)`;
`CodexProvider.ts:876,1034`). An ambient `AWS_PROFILE`/`AWS_ACCESS_KEY_ID` in the shell that
launched CMDeck therefore reaches **every** agent, not just the Bedrock instance (inferred from the
merge call. The merge function was not traced line by line). Scoping today depends on users not
exporting AWS variables globally, or blanking them per instance.

Claude Code's own Bedrock support is extensive: the `/setup-bedrock` wizard, SSO/`aws login`/
Bedrock API keys, credential caching, `awsAuthRefresh`/`awsCredentialExport`, application
inference profile ARNs and `modelOverrides`, `ANTHROPIC_BEDROCK_REGION_PREFIX`, service tiers,
Guardrails via `ANTHROPIC_CUSTOM_HEADERS`, and the Mantle endpoint
([code.claude.com/docs/en/amazon-bedrock](https://code.claude.com/docs/en/amazon-bedrock)). CMDeck
should expose this, not rebuild it.

**Can MCP servers replace native UI? Mostly yes.** Every §6 item except "which model this thread
uses" is an API that an agent can call through the AWS MCP Server (`call_aws`) or a narrower awslabs
server: KB retrieval with reranking/filter debugging, Guardrail tests, eval job submission, cost

## 5. Inert-when-disabled design

Today CMDeck is inert by construction. It has no AWS SDK, makes no AWS calls and does no credential
discovery. Bedrock traffic happens only inside a harness the user configured. Keep it that way:

- No `@aws-sdk/*` dependency. If a native piece is ever approved, add it behind a dynamic `import()`
  inside an Effect layer built only when `aws.enabled` is true, and keep it out of web/mobile bundles.
- Never call `fromNodeProviderChain` implicitly. It reads `~/.aws/*` (on this machine
  `C:\Users\Chris\.aws\credentials` is a honeypot) and may reach EC2 IMDS. Resolve only an explicitly
  named profile (`fromIni({profile})`/`fromSSO({profile})`) on user action.
- Inject credentials per provider instance only (existing env + secret refs). Prefer SSO profile or
  short-term Bedrock API key; deny long-term keys with `bedrock:bearerTokenType` conditions.
- MCP servers are opt-in per harness config. Disabled means absent from config, so no process starts.
- UI: no AWS settings section unless enabled. A Bedrock-labelled instance appears only when created.

## 6. Cost and safety controls (any resource creation)

1. **IAM is the gate, not prompts.** Give agents an inference-only role. Give MCP infra tools a
   separate profile with a permissions boundary, and use read-only by default (AWS MCP Server example
   policy restricts to read-only even when the user's role can write. Source: agent-toolkit README).
2. **Confirmation:** keep harness approval modes on for MCP write tools. awslabs servers default to
   read-only and need `--allow-write`/`ALLOW_WRITE` (ECS, EKS, SageMaker, serverless).
3. **Tagging:** require `cmdeck:owner`, `cmdeck:thread`, `cmdeck:ttl` tags (enforce with a
   `aws:RequestTag` IAM condition); activate them as cost allocation tags. Use a tagged application
   inference profile per CMDeck instance for invoice-level Bedrock attribution.
4. **TTL/cleanup:** a scheduled task (CMDeck already has scheduled tasks) lists resources past
   `cmdeck:ttl` via the MCP server and asks before deleting. Never auto-delete without confirmation.
5. **Budgets:** a monthly cost budget with forecast alerts plus a Budgets action applying a deny
   policy to the agent role. Warn that Budgets lag up to ~8-12 h and are not a hard cap. Recommend a
   dedicated AWS account (Claude Code docs).
6. **Watch ongoing costs:** managed KB index ($/GB-month), OpenSearch Serverless, AgentCore Gateway
   indexed tools, CloudWatch logs (invocation logging, AgentCore observability), real-time SageMaker
   endpoints, EC2/Fargate. Cost Explorer API calls cost $0.01 each, so never poll it.
