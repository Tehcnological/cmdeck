## 1. Overview

### Architecture in five lines (K1 §1, K2 "Orientation")

- **One Python asyncio/aiohttp "gateway" process** (about 2.5M non-test lines, about 8.5k test
  files) serving a React/Vite SPA, an Electron shell, a CLI and a dozen messaging channels.
- **ACP-provider-only.** The harness (default `kiro-cli acp`, alternatives Claude, Codex, goose,
  OpenCode, Pi and others) owns the model, tools and compaction. Every piece of "LLM work" Kiro
  does itself (memory consolidation, judges, skill detection) is a **billed background harness turn**,
  not a local model (K1 §1).
- **Storage** under `~/.kiro/crew`: JSON/JSONL files with atomic replace and advisory locks, plus
  about ten SQLite databases. One durable task queue (`kc/taskq/store.py`, `tasks.db`) carries
  TaskRunner steps, subagents and workflow agent calls.
- **Coordination lives in generated agent configs** (conductor, worker, mate, heartbeat) plus
  `kirocrew-core` MCP tools, not in orchestration code.
- **Code style not to copy.** "Facade + owner modules" with `_facade_mirror` monkeypatch seams,
  specs of 6–9k lines each, separate in-gateway "apps" per tool. The behaviour is often good; the
  volume is not a model (AGENTS.md: "smallest model that makes the correct behavior unsurprising").

### License and attribution

- Repository: **Apache-2.0** with a `NOTICE` ("KiroCrew, Copyright Amazon.com, Inc. or its
  affiliates") and a 12.6k-line `THIRD-PARTY-NOTICES` (K1 §1, K2 intro).
- **Behaviour ports need no attribution.** Nothing in this document recommends copying Kiro code:
  the language differs (Python vs TypeScript) and every recommendation is a reimplementation.
- **If code or text is copied** (prompt wording, schemas, regex lists such as
  `_INJECTION_PATTERNS`), keep the Apache-2.0 license text, state changes, and carry the `NOTICE`
  attribution into CMDeck's notices. Apache-2.0 §3 patent grant applies to contributions copied.
- Per-app licenses differ (K2): Design Tweak and Design Critique manifests say **MIT**; Papyrus is
  Apache-2.0 with `ATTRIBUTION.md` crediting "tricatte"; PPTX Maker is **MIT-0** (engine
  `aws-samples/sample-spec-driven-presentation-maker`, MIT-0); the browser `reflex` helper adapts
  `browser-use/jev-ultrafast` (MIT); the bundled OpenDyslexic font is OFL. Code Review Sage,
  Auto-Improvement, Spec Builder, Ops Mission Control and Notes have **no `license` field**; the repo

  `browser-use/browser-harness` license was not verified (K2 OQ4).
- **Trademark.** "Kiro" is an Amazon trademark. Use it only as the importer's source label.

### Telemetry and phone-home exclusions (EXC; K1 §7, K2 "Telemetry")

None of these may be ported (CMD-01, brief §10):

1. **Product metrics to Kiro, on by default**: `kc/metrics/kiro_export.py`
   `ENDPOINT="https://telemetry.us-east-1.kiro.dev/v1/metrics"`. Config cannot remove or repoint it;
   only turning local recording off stops it (`TelemetryConfig.enabled = True`).
2. **Daily anonymous beacon, on by default**: `kc/beacon.py` to `d175o3ylxqum0e.cloudfront.net`.
3. **Default-on downloads**: 610 MB embedding model and feature videos (`d3j0sthz5doyui.cloudfront.net`),
   decision-model weights (`dostcaqwrph3m.cloudfront.net`).
4. **Update checks and hosted services**: `updates.crew.kiro.dev`, `download.crew.kiro.dev`,
   `apps.crew.kiro.dev`, the Kiro relay, lease and managed-environment services.
5. **Hosted decision API by default**: Jev = TypeSafe `https://api.typesafe.ai/v1/systemone` (K2 TLS-05..08).
6. **Background inference** (consolidation, judges, skill detection, knowledge extraction) is not
   telemetry but is extra outbound inference. In CMDeck it must be opt-in, preferably local.

Whether the metrics export fires on first run before any notice is shown needs a runtime trace (K2 OQ2).

## 2. Decision vocabulary

- **Native** — build it CMDeck's way; Kiro is only a behaviour reference.
- **Adapt** — keep Kiro's model (data shape, rules) but map it onto existing CMDeck primitives.
- **Port (behaviour)** — reproduce specific Kiro behaviours closely; still a TS rewrite, no code copy.
- **Harness — expose** — the harness already does it; CMDeck only surfaces it.
- **Wait (D15)** — an upstream T3 PR covers it; do not build in parallel.
- **Defer** — not in early phases; reasons given.

All new subsystems follow D3 (fork module under `apps/server/src/fork/<module>/`, tables in
`ForkSchema.ts`, additive fork contracts, protocol version untouched).

### 3.2 Memory and learning (K1 §3)

Kiro runs **two parallel memory lineages** (global V1 Markdown + `memory.db`, per-bot V2 `memory_items`).
D6 keeps one: a single SQLite store shaped like Kiro V2 with a `scope` column
(`global | user | project:<id> | repo:<id> | bot:<id> | thread:<id>`), a revisions table and FTS5;
incognito/temporary are thread modes, not scopes.

**Conflict to resolve:** CL §2 recommends Markdown files per scope as the source of truth (OpenClaw,
Letta, Hermes) with SQLite as an index. K1 and D6 recommend SQLite rows as the source of truth with
no Markdown. D6 is the baseline; if the user wants hand-editable files, the CL composite is the
alternative. Either way provenance is stored outside content.

Poisoning defaults (K1 §3 "Memory poisoning"): provenance tag on every item
(`user_explicit | user_confirmed | agent_inferred | imported`); only user-origin items become
standing rules; tool output and fetched content never enter consolidation input; regex screening is
hygiene, not a boundary; every write is a revision. Kiro ships its origin gates **off** by default.

## 6. What not to inherit

Merged from K1 §1/§7/§8 and K2 "What NOT to inherit".

1. **Phone-home**: default product metrics (un-repointable destination), daily beacon, CDN model and
   video downloads, update checks, app catalog, Kiro relay/lease/managed environments.
2. **Hosted decision API by default** (Jev/TypeSafe) and the proprietary System One wire format as the
   only protocol.
3. **Billed background inference by default** (consolidation, judges, skill detection, knowledge
   extraction). Make it opt-in and prefer local models.
4. **Model-authored code executed in the privileged server process** (AGT-05 `exec(compile(...))`
   behind an AST blocklist).
5. **Two memory lineages**; memory-poisoning gates shipped **off**.
6. **Agents attached to the user's real browser profile** by default.
7. **Vault key as a plaintext file beside the ciphertext**; owner-facing redaction off by default.
8. **A credential file fence called "OS sandboxing"** with no egress control and nothing on Windows.
9. **Audit chains that restart per segment** and a same-user symmetric key presented as integrity.
10. **Ungated optional modules** (AWS deploy skills and routes installed at every start).
11. **Token minting by shelling `kirocrew token` over SSH/SSM** (bearer token transits SSM history).
12. **Boards** (Crew board, chat-tag columns: KCX-01/02, excluded).
13. **Architecture**: facade-mirror monkeypatch indirection; per-feature in-gateway "apps"; giant
    per-channel stacks; a second public REST API; a second durable queue beside the workflow engine;
    many small JSON stores with advisory locks instead of one SQLite database.
