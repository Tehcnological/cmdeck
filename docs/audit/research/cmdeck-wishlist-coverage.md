Architecture notes for the proposal:

- **One scheduler already has two front ends.** Scheduled tasks (prompt → thread) and workflow triggers
  (code + agents). Deterministic scripts belong in workflows; cron syntax would extend `Schedule.ts`.
- **One event pipeline exists.** `MilestoneHub` (`milestones/MilestoneHub.ts`; event kinds in
  `packages/contracts/src/milestones.ts`: `thread.run_settled`, `thread.needs_input`,
  `pr.watch_wake`, `workflow.*`) feeds MCP Events (poll/stream/webhook). It is the natural source for
  messaging adapters, usage alerts and heartbeat checks. It keeps 1,000 events in memory only.
- **Fork persistence pattern.** New fork tables (memory, notes, audit log) should follow
  `ForkSchema.ts` rather than numbered migrations, to keep upstream merges clean.
- **No outbound notification channel in CMDeck.** Agent-activity publishing (mobile push, Live
  Activities) is a no-op since `51905decad`. Any alert feature (INF-10, AUT-03, MSG-*) needs a new
  delivery path.

## 5. Open questions

1. **Ambiguous Kiro semantics.** AGT-07 Work Ledger, AGT-08 Session Ledger, AGT-09 Agent Channels,
   CHT-08 Quiet-turn indicator and AUT-03 Heartbeat monitoring are rated on plain meaning. The Kiro
   agents' findings may move them between Partial and Absent.
2. **Workflows are Labs-gated.** Many Partial→Implemented calls (AGT-05/06, AUT-02, presets for
   AGT-10/DEV-02/DEV-03) depend on promoting workflows out of Labs. Does CMDeck accept that?
3. **Can a workflow step run shell commands?** Workflow files are dynamically imported TS modules
   (`WorkflowRuntime.ts:151`), so Node imports are probably allowed **(inferred)**; not tested here.
   If so, AUT-02 needs only documentation and a helper, not a new subsystem.
4. **Stale CMDeck docs.** `docs/user/project-settings.md` §Webhook automations and
   `docs/user/mobile-notifications.md` still describe T3 Connect tunnels, held webhooks and push
   delivery that `51905decad` removed. This belongs to the CMD-02 audit.
5. **Notification gap.** With push disabled, CMDeck has no way to alert a user away from the app.
   Messaging adapters (MSG-*) could become that channel; usage alerts (INF-10) and heartbeats
   (AUT-03) depend on that decision.
6. **Memory ownership.** Every memory feature is either harness-owned or absent. The design must
   decide whether CMDeck memory is injected into harness context (per-provider adapters) or exposed
   as MCP tools (provider-neutral, lower merge burden). The existing FTS5 index and `ForkSchema.ts`
   pattern favour a small SQLite store behind MCP tools.
